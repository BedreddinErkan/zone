# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this repository.

## Project

Zone is a self-hosted AI coding agent: a TypeScript Node CLI with BYOK access to OpenAI and Anthropic. Node 22+, npm 10+.

## Common commands

```bash
npm run build         # tsc -p tsconfig.json
npm run typecheck     # tsc --noEmit
npm test              # vitest run
npx vitest run src/llm/agentLoop.dispatch.test.ts   # single file
npx vitest run -t "tier override"                    # pattern
npm run sweep         # scripts/sweep.ts — vestigial (HTTP server removed; target localhost:3000 is dead)
npm run sweep:dry     # config validation only
```

ESLint configured (`eslint.config.mjs`) but not wired to npm — use `npx eslint <path>`. The CLI runs from the *built* dist/ — rebuild after editing `src/`. `tsconfig.json` excludes `*.test.ts`, `**/__tests__/**`, `src/extension.ts` (vestigial VS Code shell); `src/test/**` is included so fixtures type-check.

## Big-picture architecture

Ink TUI → agent loop → provider adapters + tool executor + atomic patch flow. The TUI uses in-process dispatch (`src/cli/dispatch.ts`); plan mode default is plan-first (`quick`): `generateExecutionPlan` → `PlanReadyModal` prose gate → execute once (no audit).

### Entry points

- **`src/cli/index.ts`** — CLI (commander). TUI/headless fork: `isHeadless = options.print === true || !process.stdout.isTTY`. (`createServer` is still present for the `zone login` OAuth callback — ephemeral, random port, not the removed HTTP API.)

- **`src/cli/tui/index.tsx`** — Ink TUI entry (`runTui(initialPrompt, opts)`). Render: `{ exitOnCtrlC: false, alternateScreen: false }` (native scrollback). **stdoutShield monkey-patch** swallows stdout chunks matching `^\[[a-z_][a-z0-9_-]*\]\s` (`TELEMETRY_RE`); `ZONE_TUI_DEBUG=1` routes them to stderr. **stderrShield (`applyStderrInterception`)** swallows matching stderr chunks in normal mode; passes through to real stderr under `ZONE_TUI_DEBUG=1`/`ZONE_VERBOSE_LOGS=1` (never self-routes). Safety net: `runPrompt` `finally` emits a synthetic `agent_loop_complete` when not aborted. ### Multi-turn session memory (`src/llm/sessionWindow.ts`)

`buildSessionWindow(events)` is **pure, synchronous, no-I/O**, assembling the bounded window injected as `priorSessionSummary`:
- **Atomic turn events** `{type:"turn"}` — one per dispatch, written post-run in `index.tsx` via `appendFsConversationEvent` keyed on `config.repoPath` (the repoPathTrap). Fields: `userPrompt≤256B`, `summary≤2048B` (neutral-truncated), `changedFiles≤12`, `outcome` (`applied|no_change|answered|reverted`).
- **Tiered window** — Tier A: newest turn full fidelity; Tier B: older as one-line intent+paths. Hard cap `SESSION_WINDOW_MAX_BYTES=4096`; O(1) in turn count.
- **Cache-safe injection** — via `priorSessionSummary` → `sessionMemBlock` → first user message. **Never** in `assembleAgentSystemPrompt`. `SESSION_MEMORY_HEADER` shared between static directive + runtime injection (cannot desync).

- **`truncateSessionTurn`** strips surviving `APPLY_ROLLED_BACK` → `"(no net change remained during that turn)"` — never raises rollback vocabulary under a neutral header.
- **Clear GC** — `/session Clear` mints a new `sessionId`; `SessionMemoryModal.tsx` captures the old one before dispatch → `onSessionClear?.(oldId)`, best-effort unlink.
