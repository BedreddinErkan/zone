# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this repository.

## Project

Zone is a self-hosted AI coding agent: a TypeScript Node service exposing an HTTP/SSE API plus a single-page vanilla-TS web UI, with BYOK access to OpenAI, Anthropic, and Gemini. Node 22+, npm 10+.

## Common commands

```bash
npm run build         # tsc -p tsconfig.json + scripts/sync-zone-ui.cjs (UI → dist/ui)
npm run typecheck     # tsc --noEmit
npm run serve         # node dist/cli/index.js serve — requires a prior build
npm test              # vitest run
npx vitest run src/llm/agentLoop.dispatch.test.ts   # single file
npx vitest run -t "tier override"                    # pattern
npm run sweep         # scripts/sweep.ts against a running local server
npm run sweep:dry     # config validation only
```

ESLint is configured (`eslint.config.mjs`) but not wired to npm — use `npx eslint <path>`. `serve` runs the *built* CLI, not source — rebuild after editing `src/`. `tsconfig.json` excludes `*.test.ts`, `**/__tests__/**`, and `src/extension.ts` (vestigial VS Code shell); `src/test/**` is included so fixtures type-check (never imported from production).

## Big-picture architecture

Browser UI → Express server → agent loop → provider adapters + tool executor + atomic patch flow. Progress streams over SSE on `/api/progress`. A TTY-attached Ink TUI shares the same agent loop via in-process dispatch (`src/cli/dispatch.ts`), bypassing HTTP. HTTP `/api/patch` gates via `runAuditPipeline()` (transport-agnostic `emit`); the TUI default plan-mode path uses the cheaper `requestPlanApproval` gate (no audit — see plan mode below).

### Atomic patch flow

- Driver: `src/core/runLlmPatchFlow.ts`. Patches staged in memory (`Map<string,string>`), validated with `tsc --noEmit` + per-language checkers (`syntaxCheckers.ts` — TS + Python always on; Go/Ruby/Java opt-in via `ZONE_EXPERIMENTAL_SYNTAX_CHECKERS`; all `gracefulSkip:true`).
- Apply: `src/core/applyLlmPatches.ts` — all-or-nothing flush, auto-rollback. **Staging flush invariant (`840d816`):** `apply_patch`/`write_file` write to the staging map via `stagedWrite()`; the single disk-write point is `finalizeStaging()` (`staging.ts`). `persistStagingOnError()` is called before every early-exit return (`token_budget_exceeded`, `loop_detected`/`scope_block`, `compaction_exhausted`) so staging survives runs that don't reach `finalizeRun` (uses `verifyMode:"warn"` — partial work persists even if tsc finds issues). `natural_completion`/`max_iterations` go through `finalizeRun` → `verifyAndFinalize` → `finalizeStaging` (no double-flush). Tool messages: `"Patch staged: N block(s)"` / `"File staged: N chars"`.
- AST/conversion: `astPatchFallback.ts`, `patchConversion.ts`, `src/patch-generation/`. Decision/audit: `decisionEngine.ts` + `src/core/decision/`; `src/audit/`.
- **Scope audit gating (`auditMode.ts`):** `shouldRunAudit`/`isLowRiskPlan`. In `auditMode=auto`, audit skips when `isLowRiskPlan`: ≤3 distinct files, tier ≠ complex, no `subagentEligible`, no rename/move verb. Also skipped when `skipAudit || skipPhase1`. When audit runs, the sub-investigation inherits the parent model — NO silent downgrade (Haiku-downgrade reverted 8fd6d85).
- **Runtime write-scope guard (`src/tools/scopeGuard.ts`):** `checkWriteScope` gates every `apply_patch`/`write_file` (`toolExecutor.ts:1566`,`:2439`) against the union of `plan.steps[*].filesLikely`. Exact-match after `normalizePath`, with **one tolerance**: same-directory + same-stem + both extensions in the **TS/JS family** (`ts/tsx/js/jsx/mts/cts/mjs/cjs`) → allowed. Cross-family stays exact (`.py` ≠ `.ts`) — plan-LLM extension hallucination (`store.ts` vs `store.tsx`) is non-fatal. `maybeExpandScopeForVerifyDiagnostic` widens scope when `parseVerificationError` extracts a `failingFile`. `maybeExpandScopeForSymbolMatch` (`091564a`) widens for `refactor`/`complex_multi_file` when the blocked file contains a plan-named symbol (grep-grounded). Block returns `error:"apply_patch_blocked_out_of_plan_scope"`; emits `[zone-scope-block]`. **`refactor` + `complex_multi_file` bypass plan-scope enforcement entirely (`c0b6a5a`)** — `checkWriteScope` returns null for these two (net-negative on rename/multi-file); all other archetypes still enforce. **Defense-in-depth:** `executionPlan.ts` instructs the LLM to copy paths VERBATIM from RELEVANT FILES.
- **Scope-block circuit breaker (`handleToolResult.ts` step 11.5):** `consecutiveScopeBlocks` counts consecutive scope-blocked writes; resets on any successful write. At 3 → Pattern A coaching nudge (extension-mismatch hint + "end with FINAL SUMMARY"). At 5 → `early_exit` via `synthesizeScopeBlockExit` (`terminationReason:"scope_block_circuit_breaker"`) + `scope_block_circuit_terminal` SSE. Without this a scope mismatch the family-tolerance can't fix burns the whole run (original symptom: 27 iter / $1.96 / +0/−0 diff). **Effectively unreachable for `refactor`/`complex_multi_file`** (scope enforcement bypassed upstream).

### Multi-turn session memory (`src/llm/sessionWindow.ts`)

Written as part of the Roadmap #1 capability: `buildSessionWindow(events)` is a **pure, synchronous, no-I/O** function that assembles the bounded multi-turn context window injected as `priorSessionSummary`. Key invariants:
- **Atomic turn events** `{type:"turn"}` — one per completed dispatch, written post-run in `index.tsx` via `appendFsConversationEvent` keyed on `config.repoPath` (NOT `process.cwd()` — the repoPathTrap). Fields: `userPrompt≤256B`, `summary≤2048B` (neutral-truncated via `truncateSessionTurn` — no `APPLY_ROLLED_BACK` marker isolation), `changedFiles≤12`, `outcome` enum (`applied|no_change|answered|reverted`).
- **Tiered window** — Tier A: newest turn at full fidelity; Tier B: older turns as one-line `earlier you asked to "..."; files: a.ts` (intent+paths only, no summary). Hard cap `SESSION_WINDOW_MAX_BYTES=4096` on the assembled string; cost O(1) in turn count.
- **Cache-safe injection** — window goes through the existing `priorSessionSummary` seam → `sessionMemBlock` → concatenated into `userContent` (first user message). **Never** in `assembleAgentSystemPrompt`. `SESSION_MEMORY_HEADER` constant is shared between the static directive and the runtime injection so they cannot desync.
- **Double-injection suppression** — when `sessionMemBlock` is non-empty, the `PRIOR RUN CONTEXT` block is suppressed (the window already carries the most recent turn with neutral framing). Belt-and-suspenders: FS fallback in `runLlmPatchFlow.ts` is also skipped when `priorSessionSummary` is supplied.
- **`truncateSessionTurn`** (not `truncatePriorRunSummary`) — strips any surviving `APPLY_ROLLED_BACK` text to `"(no net change remained during that turn)"`. Never raises rollback vocabulary under a neutral header.
- **Clear GC** — `/session Clear` mints a new `sessionId`; `SessionMemoryModal.tsx` captures the old `sessionId` before dispatch and calls `onSessionClear?.(oldId)` (callback threaded from `index.tsx` via `App.tsx`, has closure over `config.repoPath`). Best-effort unlink of the orphaned `.jsonl`, never throws.
