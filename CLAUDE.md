# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Zone is a self-hosted AI coding agent: TypeScript Node service that exposes an HTTP/SSE API plus a single-page vanilla-TS web UI, with BYOK access to OpenAI and Anthropic. Node 22+, npm 10+.

## Common commands

```bash
npm run build         # tsc -p tsconfig.json + scripts/sync-zone-ui.cjs (UI → dist/ui)
npm run typecheck     # tsc --noEmit
npm run serve         # node dist/cli/index.js serve  — requires a prior `build`
npm test              # vitest run

# Single test file / pattern:
npx vitest run src/llm/agentLoop.dispatch.test.ts
npx vitest run -t "tier override"

# Sweep harness (variance dashboard input):
npm run sweep         # runs scripts/sweep.ts against a running local server
npm run sweep:dry     # config validation only
```

ESLint is configured (`eslint.config.mjs`) but not wired to npm — invoke `npx eslint <path>` directly.

The `serve` script runs the *built* CLI, not source — rebuild before re-`serve` after editing `src/api/`, `src/llm/`, `src/core/`, etc. `src/ui/index.html` is copied to `dist/ui/` by `scripts/sync-zone-ui.cjs` as part of `npm run build`.

`tsconfig.json` excludes `*.test.ts`, `**/__tests__/**`, and `src/extension.ts` (a vestigial VS Code extension shell bundled separately by `esbuild.js`, NOT in the server build). `src/test/**` is included so `src/test/fixtures/toolExecutorMock.ts` is type-checked; never imported from production.

## Big-picture architecture

Browser UI → Express server → agent loop → provider adapters + tool executor + atomic patch flow. Progress streams over SSE on `/api/progress`. A TTY-attached Ink TUI shares the same agent loop via direct in-process dispatch (`src/cli/dispatch.ts`), bypassing the HTTP layer — the **TUI.7.F audit pipeline extraction** unified the audit gate behind a transport-agnostic `emit` callback so both paths share the same `runAuditPipeline()`.

**Tool execution + command approvals**

- `src/tools/toolExecutor.ts` implements every tool the LLM can call (`read_file`, `write_file`, `apply_patch`, `run_command`, etc.). Definitions in `src/tools/toolDefinitions.ts`.

"anon"` so worker subagents share the parent run's cache (consistent with K.2 staging-file inheritance).
