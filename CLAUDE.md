# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this repository.

## Project

Zone is a self-hosted AI coding agent: a TypeScript Node service exposing an HTTP/SSE API plus a single-page vanilla-TS web UI, with BYOK access to OpenAI, Anthropic, and Gemini. Node 22+, npm 10+.

## Common commands

```bash
npm run build         # tsc -p tsconfig.json + scripts/sync-zone-ui.cjs (UI → dist/ui)
npm run typecheck     # tsc --noEmit
npm run serve         # node dist/cli/index.js serve — requires a prior build
npm test              # vitest run
npx vitest run src/llm/agentLoop.dispatch.test.ts   # single file
npx vitest run -t "tier override"                    # pattern
npm run sweep         # scripts/sweep.ts against a running local server
npm run sweep:dry     # config validation only
```

ESLint is configured (`eslint.config.mjs`) but not wired to npm — use `npx eslint <path>`. `serve` runs the *built* CLI, not source — rebuild after editing `src/`. `tsconfig.json` excludes `*.test.ts`, `**/__tests__/**`, and `src/extension.ts` (vestigial VS Code shell, bundled separately by `esbuild.js`); `src/test/**` is included so fixtures type-check (never imported from production).

## Big-picture architecture

Browser UI → Express server → agent loop → provider adapters + tool executor + atomic patch flow. Progress streams over SSE on `/api/progress`. A TTY-attached Ink TUI shares the same agent loop via in-process dispatch (`src/cli/dispatch.ts`), bypassing the HTTP layer — the TUI.7.F audit extraction unified the audit gate behind a transport-agnostic `emit` callback so both paths share `runAuditPipeline()`.

### Atomic patch flow

- Driver: `src/core/runLlmPatchFlow.ts`. Patches staged in memory (`Map<string,string>` in `agentLoop.ts`), validated with `tsc --noEmit` plus per-language checkers (`src/tools/syntaxCheckers.ts` — TS + Python always on; Go/Ruby/Java opt-in via `ZONE_EXPERIMENTAL_SYNTAX_CHECKERS`; all `gracefulSkip:true`).
- Apply: `src/core/applyLlmPatches.ts` — all-or-nothing flush, auto-rollback on failure. **Staging flush invariant (`840d816`):** `apply_patch`/`write_file` write to the staging map via `stagedWrite()`; the single disk-write point is `finalizeStaging()` in `src/llm/verification/staging.ts`. `persistStagingOnError()` (module-private in `agentLoop.ts`) is called immediately before every early-exit return (`token_budget_exceeded`, `loop_detected`/`scope_block` via `handleToolResult` early_exit, `compaction_exhausted`) so staging survives runs that don't reach `finalizeRun`. Uses `verifyMode:"warn"` + `framework:undefined` — partial work persists even if tsc finds issues. `natural_completion` and `max_iterations` still go through `finalizeRun` → `verifyAndFinalize` → `finalizeStaging` (no double-flush). Tool result messages are `"Patch staged: N block(s)"` / `"File staged: N chars"` to reflect deferred semantics.
- AST/conversion: `src/core/astPatchFallback.ts`, `patchConversion.ts`, `src/patch-generation/`.
- Decision/audit: `src/engine/decisionEngine.ts` + `src/core/decision/`; `src/audit/` snapshots + diffs.
- **Scope audit gating (`src/llm/auditMode.ts`):** `shouldRunAudit`/`isLowRiskPlan`. In `auditMode=auto`, audit is skipped when `isLowRiskPlan` is true: ≤3 distinct files across all steps (read-only included — `PlanStep` has no intent field), tier ≠ complex, no step `subagentEligible`, no rename/move verb. Emits `[zone-audit-skipped]`. Also skipped when `_serverPipelineCfg?.skipAudit || skipPhase1`. When audit *does* run, the sub-investigation inherits the parent run's model — Zone does NOT silently downgrade (Haiku-downgrade reverted 8fd6d85). Extracted to `src/llm/auditPipeline.ts` (server + dispatch consume it via `emit`).
- **Runtime write-scope guard (`src/tools/scopeGuard.ts`):** `checkWriteScope` gates every `apply_patch`/`write_file` (`toolExecutor.ts:1566`, `:2439`) against the union of `plan.steps[*].filesLikely`. Path comparison is exact-match after `normalizePath` (strips `./`/leading `/`, repoPath-aware), with **one tolerance**: same-directory + same-stem + both extensions in the **TS/JS family** (`ts/tsx/js/jsx/mts/cts/mjs/cjs`) → allowed. Cross-family stays exact (`.py` ≠ `.ts`, `.json` ≠ `.ts`). Plan-LLM extension hallucination (listing `store.ts` when the file is `store.tsx`) is therefore non-fatal. `maybeExpandScopeForVerifyDiagnostic` separately widens scope when `parseVerificationError` extracts a `failingFile` from build/test stderr (mutates `steps[0].filesLikely`). `maybeExpandScopeForSymbolMatch` (`091564a`) widens scope for `refactor`/`complex_multi_file` archetypes when the blocked file contains a symbol named in the plan objective (grep-grounded expansion, `symbol_match` reason). Block returns `error:"apply_patch_blocked_out_of_plan_scope"` / `error:"write_file_blocked_out_of_plan_scope"`; emits `[zone-scope-block]`. **`refactor` + `complex_multi_file` archetypes bypass plan-scope enforcement entirely (`c0b6a5a`):** `checkWriteScope` returns null unconditionally for these two archetypes — scope enforcement was net-negative on rename/multi-file tasks where the plan LLM can't enumerate all affected files upfront. All other archetypes (`targeted_fix`, `simple_add`, `debug`, `question`, `investigation`) still enforce scope. **Defense-in-depth at the plan layer:** `executionPlan.ts` prompt instructs the LLM to copy paths VERBATIM from RELEVANT FILES (no extension guessing) — the family-tolerance is the runtime backstop, not the primary mechanism.
- **Scope-block circuit breaker (`handleToolResult.ts` step 11.5):** `ToolEventContext.consecutiveScopeBlocks` counts consecutive scope-blocked writes; resets to 0 on any successful `apply_patch`/`write_file`. At 3 → Pattern A coaching nudge appended to the just-pushed `role:"tool"` message (extension-mismatch hint + "end with FINAL SUMMARY"). At 5 → `early_exit` via `deps.synthesizeScopeBlockExit` (returns `AgentLoopResult` with `terminationReason:"scope_block_circuit_breaker"`) + `scope_block_circuit_terminal` SSE event (`blockedCount`, status `error`). Mirrors the Compact.0.1 skip-guard precedent — a repeated no-op must not silently burn the budget. Without this guard a plan-LLM scope mismatch the family-tolerance can't fix (cross-directory rename, etc.) burns the whole run; the original dogfood symptom was 27 iter / $1.96 / +0/−0 diff terminating on `token_budget_exceeded`. **Note:** circuit breaker is effectively unreachable for `refactor`/`complex_multi_file` since scope enforcement is bypassed upstream.

### Tool execution + command approvals

- `src/tools/toolExecutor.ts` implements every tool (`read_file`, `write_file`, `apply_patch`, `run_command`, etc.). Definitions in `toolDefinitions.ts`. **Staging-awareness matrix:** `read_file` → staging-first via `stagedRead()` ✓; `search_in_files` rg path → wrapped in `withStagingTempFlush` (`840d816`) ✓; `find_references` → passes `stagingFiles` to `buildDependencyGraph` (`840d816`) ✓; `run_command` → `withStagingTempFlush` ✓; `list_files` fast-glob → disk-only (staged new files are invisible to `list_files`).

- `run_command` flows through `src/api/commandApprovals.ts`: an allowlist auto-approves safe commands (no shell metachars; prefix matches `SAFE_COMMAND_PREFIXES`); previously-trusted commands auto-approve for the run; everything else creates a pending approval → `/api/approve-command`. "anon"` (workers share the parent cache). Cleared in the `finally` gated on `!input.subagent`; `[zone-command-cache-summary]` at run end.
