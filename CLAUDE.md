## Big-picture architecture

Ink TUI → agent loop → provider adapters + tool executor + atomic patch flow. The TUI uses in-process dispatch (`src/cli/dispatch.ts`); plan mode default is plan-first (`quick`): `generateExecutionPlan` → `PlanActionPrompt` prose gate → execute once (no audit).

- **Anthropic prompt caching** on by default (`ZONE_ENABLE_MESSAGE_CACHE=1`). Two breakpoints in `convertParams.ts`: last-tool marker (caches tools alone, ~3879 tok — measured against the per-call usage log, `docs/deferred-work.md` item 161; not system+tools as earlier assumed here) + last-persistent-user-message marker. **The non-obvious step:** `translateMessages` renders every `role:"tool"` message as a `role:"user"` message carrying a `tool_result` block, so **marker #2 lands on the LAST TOOL RESULT and advances every iteration**. The conversation is therefore *inside* the cached prefix and is read at 0.1x — it is not an uncached tail. Every wrong cost derivation in this repo has missed that one step. R.2 stale-read pruning and the U.1 shim were **deleted** (`1b64739a`): pruning rewrote an already-cached message, which invalidated the prefix and cost 2.3x measured, and U.1 had been discarding every elision since it landed, making `[zone-context-pruned]`'s `charsSaved` phantom.

  **Cache invariant — APPEND-ONLY, not "no user messages".** Tool results add a `role:"user"` message every iteration and that is harmless; the marker simply advances with them. What breaks caching is content *behind* the marker **changing**: a transient user notice that appears and then disappears, an eviction that rewrites an earlier turn (R.2, deleted), or a summary hoisted into the system prompt (compaction, fixed `3ae390fe`). A processor may append; it may not rewrite a message already sent. Pinned by `src/llm/history/cachePrefixStability.test.ts`. **Pattern A (preferred):** backward-scan `responseInput` for the last `role:"tool"`, string-concat the notice into its content (Phase J coaching, loop/soft-iter/mid warns). **Pattern B (fallback):** push `role:"user"` only when no preceding tool message exists. **E.3 manifest** (`ManifestInjectionProcessor`) appends a `role:"user"` message every iter when `entryCount > 0`. **Fix A (`applyMessageCacheBreakpoint2`, cacheControlHelpers.ts):** the scan SKIPS manifest messages (`MANIFEST_CONTENT_PREFIX = "## Files already read this run"`) and marks the last PERSISTENT user message — the manifest varies per iter.
