# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this repository.

## Project

Zone is a self-hosted AI coding agent: a TypeScript Node service exposing an HTTP/SSE API plus a single-page vanilla-TS web UI, with BYOK access to OpenAI and Anthropic. Node 22+, npm 10+.

## Common commands

```bash
npm run build         # tsc -p tsconfig.json + scripts/sync-zone-ui.cjs (UI → dist/ui)
npm run typecheck     # tsc --noEmit
npm run serve         # node dist/cli/index.js serve — requires a prior build
npm test              # vitest run
npx vitest run src/llm/agentLoop.dispatch.test.ts   # single file
npx vitest run -t "tier override"                    # pattern
npm run sweep         # scripts/sweep.ts against a running local server
npm run sweep:dry     # config validation only
```

ESLint is configured (`eslint.config.mjs`) but not wired to npm — use `npx eslint <path>`. `serve` runs the *built* CLI, not source — rebuild after editing `src/`. `tsconfig.json` excludes `*.test.ts`, `**/__tests__/**`, and `src/extension.ts` (vestigial VS Code shell, bundled separately by `esbuild.js`); `src/test/**` is included so fixtures type-check (never imported from production).

## Big-picture architecture

Browser UI → Express server → agent loop → provider adapters + tool executor + atomic patch flow. Progress streams over SSE on `/api/progress`. A TTY-attached Ink TUI shares the same agent loop via in-process dispatch (`src/cli/dispatch.ts`), bypassing the HTTP layer — the TUI.7.F audit extraction unified the audit gate behind a transport-agnostic `emit` callback so both paths share `runAuditPipeline()`.

### Tier classification — read this before changing it

- `src/llm/taskClassifier.ts` classifies tasks into `simple`/`medium`/`complex` before dispatch, gating token budget, iteration cap, and subagent quota. **Deterministic by design:** temperature 0, no PRNG, djb2-hashed in-process cache, low-confidence (`<0.5`) always falls back to `medium`. See `docs/determinism.md`. The confidence threshold is a module-level constant, not user-configurable.

- **L5.0 archetype dimension:** `TaskClassification` carries `archetype: TaskArchetype` + `archetypeConfidence`. 7-value union: `simple_add | targeted_fix | refactor | debug | investigation | question | complex_multi_file`. Boundary disambiguation ("Add X" + 1 file = simple_add; "failing test + fix" = debug; "list/enumerate/show all" + filesystem scope = question). Parser falls back to `complex_multi_file`; `investigationFlow.ts` hardcodes `investigation,1.0`. ≥80% accuracy gate in `taskClassifier.archetype.test.ts` (40 tasks, 120s timeout — **API-consuming, do NOT run in local-only CI**).

- **L5.1b-1 archetype dispatcher (`src/llm/archetypeDispatcher.ts`):** Pure module, no I/O. ### Atomic patch flow

- Driver: `src/core/runLlmPatchFlow.ts`. Patches staged in memory, validated with `tsc --noEmit` plus per-language checkers (`src/tools/syntaxCheckers.ts` — TS + Python always on; Go/Ruby/Java opt-in via `ZONE_EXPERIMENTAL_SYNTAX_CHECKERS`; all `gracefulSkip:true`).
- Apply: `src/core/applyLlmPatches.ts` — all-or-nothing flush, auto-rollback on failure.
- AST/conversion: `src/core/astPatchFallback.ts`, `patchConversion.ts`, `src/patch-generation/`.
- Decision/audit: `src/engine/decisionEngine.ts` + `src/core/decision/`; `src/audit/` snapshots + diffs.
- **Scope audit gating (`src/llm/auditMode.ts`):** `shouldRunAudit`/`isLowRiskPlan`. In `auditMode=auto`, audit is skipped when `isLowRiskPlan` is true: ≤3 distinct files across all steps (read-only included — `PlanStep` has no intent field), tier ≠ complex, no step `subagentEligible`, no rename/move verb. Emits `[zone-audit-skipped]`. Also skipped when `_serverPipelineCfg?.skipAudit || skipPhase1`. When audit *does* run, the sub-investigation inherits the parent run's model — Zone does NOT silently downgrade (Haiku-downgrade reverted 8fd6d85). Extracted to `src/llm/auditPipeline.ts` (server + dispatch consume it via `emit`).

### Tool execution + command approvals

- `src/tools/toolExecutor.ts` implements every tool (`read_file`, `write_file`, `apply_patch`, `run_command`, etc.). Definitions in `toolDefinitions.ts`.
- `read_file` on files >10K chars checks a module-scope `outlineCache` Map (key `filePath:sha256_16hex`, content-addressed) before `generateFileOutline` (Lever 4.A, 55b517c). Hits return a ~280-char stub; `apply_patch` calls `evictOutlineCacheForFile`. LRU cap 50. Emits `[zone-outline-cache]`. `clearOutlineCacheForTest()` exported.
- `run_command` flows through `src/api/commandApprovals.ts`: an allowlist auto-approves safe commands (no shell metachars; prefix matches `SAFE_COMMAND_PREFIXES`); previously-trusted commands auto-approve for the run; everything else creates a pending approval → `/api/approve-command`. Trust is per-`runId`, cleared on completion/cancellation. Full walkthrough: `docs/architecture/run-command-flow.md`. **Command memoization (Phase 2, 9ed9736):** `run_command` checks a module-level `Map<effectiveRunId, PerRunCache>` (`runCommandCaches`). Memoizable commands (`npm test/build/typecheck`, `npx/vitest`, `tsc`) are fingerprinted as `SHA256(command|sortedStagingHash)` — same command + same staging → cache hit, execution skipped. `effectiveRunId = subagent?.parentRunId ?? runId ?? "anon"` (workers share the parent cache). Cleared in the `finally` gated on `!input.subagent`; `[zone-command-cache-summary]` at run end. Exports: `isMemoizableCommand`, `computeCommandFingerprint`, `clearCommandCacheForRun`, `clearCommandCacheForTest`. **Do NOT memoize side-effect commands** (git commit, file writes) — the whitelist is intentionally narrow. Tests: `toolExecutor.commandMemoization.test.ts` (T.1–T.8; T.8 covers subagent parentRunId inheritance).
